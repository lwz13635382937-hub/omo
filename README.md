# ChatGPT 自动备份扩展（MVP）

> 目标：防止用户忘记手动导出导致聊天记录丢失。

这是一个 **Edge/Chrome Manifest V3** 扩展。它会在 ChatGPT 网页中自动监听聊天消息变化，把当前会话暂存到本地；当检测到离开会话（如刷新、关闭标签页、切换到别的会话）时，自动尝试导出 JSON，并在导出成功后清理该会话缓存。

---

## 1) 这个插件做什么

- 在 `chatgpt.com` / `chat.openai.com` 页面注入 content script。
- 使用 `MutationObserver` 自动监听消息 DOM 变化。
- 识别 `user` / `assistant` 消息，按结构化 JSON 保存：
  - `role`
  - `content`
  - `timestamp`
  - `blocks`（预留扩展，当前支持文本和代码块）
- 临时缓存保存到 `chrome.storage.local`。
- 在以下场景尝试自动导出：
  - 关闭标签页（`beforeunload` / `pagehide`）
  - 刷新页面
  - 切换到其他会话（通过 URL 变化检测）
- 导出成功后自动删除该会话缓存；导出失败则保留缓存。
- 提供 popup 面板：
  - 显示插件启用状态
  - 显示当前会话 id
  - 显示是否有缓存
  - 手动导出按钮
  - 手动清理按钮

---

## 2) 如何在 Edge 本地加载

1. 打开 Edge，进入：`edge://extensions/`
2. 打开右上角 **开发人员模式**。
3. 点击 **加载解压缩的扩展**。
4. 选择本项目目录（包含 `manifest.json` 的文件夹）。
5. 扩展加载成功后，固定到工具栏方便查看 popup 状态。

> Chrome 同理：`chrome://extensions/`。

---

## 3) 如何测试

建议按下面流程验证 MVP：

1. 打开 ChatGPT 页面并进入某个会话。
2. 发送几条新消息（包含普通文本、代码块）。
3. 点击扩展 popup：
   - 应看到“已启用”
   - 当前会话 id
   - 缓存状态显示有消息条数
4. 在同会话内继续对话，稍等 1 秒，再看 popup：缓存条数应更新。
5. 切换到另一个会话：
   - 扩展会尝试自动导出上一个会话 JSON。
   - 浏览器默认下载目录中应出现 `ChatGPT-Backups/*.json`。
6. 刷新页面或关闭标签页：
   - 同样会触发自动导出尝试。
7. 在 popup 点击“手动导出 JSON”：
   - 应立即下载一份当前会话 JSON。
8. 在 popup 点击“手动清理缓存”：
   - 缓存状态应变为“暂无缓存”。

## 4) 当前已知限制

1. **ChatGPT DOM 结构可能变化**：
   - 当前依赖 `[data-message-author-role]` 等选择器，未来页面改版时可能需更新。
2. **页面关闭时导出不保证 100% 成功**：
   - `beforeunload/pagehide` 是“尽力而为”机制，浏览器可能中断异步流程。
3. **消息去重仍是简单策略**：
   - 目前按快照比较更新缓存，复杂编辑场景可能出现重复文本。
4. **公式/表格为降级保存**：
   - 当前按纯文本块保存，不做高保真结构还原。
5. **会话 ID 识别基于 URL**：
   - 主路径 `/c/<id>` 可靠；新建会话页使用 `path_root` 这类 fallback id。

---

## 5) 后续可以怎么扩展

1. 增强消息解析：
   - 单独抽取公式（LaTeX）、表格结构、图片链接、附件元数据。
2. 增强可靠性：
   - 结合 `chrome.alarms` 或定期后台重试未成功导出的缓存。
3. 增加设置页：
   - 允许用户自定义导出目录、文件命名、是否弹窗确认。
4. 增加会话历史管理：
   - 在 popup 中列出所有缓存会话并支持按会话导出。
5. 数据兼容与版本化：
   - 引入更完整的 `schemaVersion` 演进策略。

---

## 项目结构

- `manifest.json`：扩展配置（MV3）
- `content.js`：页面监听、消息解析、缓存、自动触发导出
- `service_worker.js`：执行导出下载、导出成功后清理缓存
- `popup.html`：简单控制面板 UI
- `popup.js`：popup 状态读取、手动导出/清理逻辑
- `styles.css`：popup 样式
